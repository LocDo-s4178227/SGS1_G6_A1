# Shopping Cart and User Account Features

| Feature | Description | User | URL / Endpoint | Data and Database Connection | Completion Status |
|---|---|---|---|---|---|
| Browse marketplace | Allows users to view, search, filter, and sort custom marketplace requests and accepted offers. | Customer or professional | `shopping_cart/products.html`<br>`GET /api/marketplace` | Retrieves marketplace data built from persisted discussion threads and replies. | Completed and manually tested. |
| Add item to cart | Allows a logged-in user to select a marketplace request with a positive accepted price and add it to the cart. Duplicate items are rejected. | Customer or professional | `shopping_cart/products.html`<br>`discuss_forum/wishlist.html`<br>`POST /api/cart/:sessionId/items` | Creates a cart item containing `productId`, `quantity`, `unitPrice`, and `textDetails`. The item is stored in the session cart in JSON or MongoDB. | Completed and manually tested. |
| View cart | Displays selected items, their source discussion thread, accepted price, status, item count, and order summary. | Logged-in user with a session cart | `shopping_cart/cart.html`<br>`GET /api/cart/:sessionId` | Retrieves the cart identified by `sessionId` from the `carts` collection or JSON `carts` object. | Completed and manually tested. |
| Update cart item | Updates the quantity or display details of an existing cart item. | User with access to the session cart | `PUT /api/cart/:sessionId/items/:itemId` | Updates `quantity` and `textDetails` in the matching cart item and persists the cart. The backend validates that quantity is a positive integer. | Backend completed and API validation tested. A visible quantity editor is not currently shown on the cart page. |
| Remove cart item | Removes an item from the cart and refreshes the cart list and totals. | User with access to the session cart | `shopping_cart/cart.html`<br>`DELETE /api/cart/:sessionId/items/:itemId` | Deletes the matching item from `carts[sessionId].items` and saves the updated cart. | Completed and manually tested. |
| Calculate cart summary | Calculates the subtotal, service fee, tax, total, and item count before checkout. | User with items in the cart | `shopping_cart/cart.html`<br>Frontend `updateOrderSummary(items)` | Reads `unitPrice` and `quantity` from cart items. Final totals are recalculated by the checkout endpoint. | Completed and manually tested with cart changes. |
| Checkout and create order | Validates delivery and payment details, creates an order, clears the cart, and returns an order number. | User with a non-empty cart | `shopping_cart/checkout.html`<br>`POST /api/orders/checkout/:sessionId` | Copies cart items into `orders`, stores delivery data and limited payment data, calculates totals, and empties the session cart. | Backend completed and validation tested. Hosted checkout-page wiring should be verified before demonstration. |
| Register account | Creates a new customer or professional account after validating the email, username, and password. | New visitor | `user_account/auth.html`<br>`POST /api/auth/register` | Creates a user record with ID, credentials, `userType`, profile defaults, preferences, and active status in JSON or MongoDB. | Completed and manually tested. |
| Login and retrieve session | Authenticates a user by email or username and creates an authenticated session. | Registered active user | `user_account/auth.html`<br>`POST /api/auth/login`<br>`GET /api/auth/session` | Retrieves the user from `users`, creates an in-memory session, and sends the HttpOnly `rshop_session` cookie. | Completed and manually tested. Sessions are not persisted after backend restart. |
| Logout | Ends the current session and removes the local user state. | Logged-in user | Shared navigation<br>`POST /api/auth/logout` | Deletes the in-memory session, clears the session cookie, and removes user data from local storage. | Completed and manually tested. |
| View profile | Displays the user's name, email, contact details, description, and profile picture. | Logged-in user | `user_account/profile.html`<br>`GET /api/auth/user/:id` | Retrieves the matching user record while excluding the password from the response. | Completed and manually tested. |
| Update profile | Allows a user to update their name, email, phone, location, description, and profile picture. | Logged-in user | Profile tab<br>`PUT /api/auth/user/:id` | Updates allowed fields in the `users` record. Email format and duplicate email validation are applied. | Completed and manually tested. The backend should additionally enforce that the requested ID belongs to the logged-in user. |
| Change password | Allows a user to replace the current password with a strong new password after validation. | Logged-in user | Security tab<br>`POST /api/auth/change-password` | Reads and updates the password field in the `users` record after checking the current password and strength rules. | Completed and frontend/API validation implemented. Use a disposable account for testing. |
| Forgot and reset password | Generates a temporary reset token and allows the user to set a new strong password. | Active user who cannot log in | `user_account/auth.html`<br>`POST /api/auth/forgot-password`<br>`POST /api/auth/reset-password` | Reads the user from `users`; stores the reset token in backend memory for 15 minutes; persists the new password to the user record. | API feature completed and validation implemented. Reset tokens are not persisted after restart. |
| Manage notification preferences | Enables or disables email, message, and new-request notifications. | Logged-in user | Account tab<br>`PUT /api/auth/user/:id` | Updates the embedded `users.preferences` object containing three Boolean settings. | Completed and manually tested. |
| Deactivate account | Marks the account as inactive and logs the user out. | Logged-in user | Account tab<br>`PUT /api/auth/user/:id/deactivate` | Updates `users.active` to `false`; login and session checks reject inactive accounts. | Completed and manually tested with a disposable account. The backend should add an owner-ID check. |
| Delete account | Permanently deletes the account after email and password confirmation. | Logged-in user | Account tab<br>`DELETE /api/auth/user/:id` | Deletes the user record from the JSON `users` object or MongoDB `users` collection. | Completed and manually tested with a disposable account. The backend should add an owner-ID check. |

## Testing Note

The features were checked through the frontend flows and backend API validation scenarios. The current backend `package.json` does not contain a configured automated test suite, so the completion statements above refer to implementation and manual/API validation rather than automated test coverage.
